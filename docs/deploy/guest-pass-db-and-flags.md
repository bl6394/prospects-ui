# Guest Pass — database scripts and feature flags: rollout and rollback runbook (Sprint 0005 E1)

**Purpose.** DT-21555 adds seven production columns (`CATALOGITEMS.CGI_GUEST_PASS`, `CGI_GUEST_PASS_VISITS`, `CGI_GUEST_PASS_CONTRACT_DAYS`; `SALEITEMS.SAI_GUEST_PASS`, `SAI_GUEST_PASS_VISITS`, `SAI_GUEST_PASS_CONTRACT_DAYS`; `SPL_EXTENSIONS.SPLEX_PROSPECT_LIABILITY`) and the `ADD_GUEST` email template rows. Every code path that reads or writes them — in `datatrak` (M&O, PR #6643 + the gating PR onto its branch), in `datatrak-service` (the `.spr` layer the Guest Pass BFF reads) and in the BFF's consumption — sits behind a club-targetable LaunchDarkly flag that defaults **off**. This runbook is the order in which the scripts, the code and the flags move, per environment, with an owner, a verification and a rollback per step, and the stop rules. Nothing in it is dated; owners are slots until kickoff (CF-25).

**Sources.** `docs/sprints/SPRINT-0005.md` §Architecture 7 (rollout order), §Use Cases U3/U7/U11/U13; `docs/contracts/short-term-pass-bff.md` §8a(e) (field table, keys); `docs/DT-21555-guest-pass-email-prd/` (scripts, handoff, review G8/G9/G14); `docs/validation/guest-pass-pilot-gates.md` (V-P1a is this runbook's rows).

**Rules that hold in every environment**

1. **Scripts before any flag.** M&O page reads and writes do **not** self-heal on a missing column (RQ-14 — they fail loudly by design); the POS hook is wrapped so a missing column never fails a sale (U11). Turning `MO_guest_day_pass_DT-21555` on for a club whose database lacks the columns breaks that club's catalog-item and Edit Club pages until the flag is off again. **Never flip the M&O flag before R1 is verified in that environment.**
2. **Flags off before any drop.** Oracle DDL is not a transaction. Dropping a column while any instance still evaluates a flag as `true` (or still runs a statement planned with the column) produces `ORA-00904` on live traffic and, for the M&O writes, data loss. The order is always: BFF exposure off → both DataTrak flags **observed off on every instance** → drain in-flight work → export the new values → DBA rollback.
3. **Observed, never inferred.** LaunchDarkly propagation and SDK caching mean "I flipped it" is not "it is off". Each DataTrak instance is observed (a flagged request answers the off shape / the off page) before the next step. The BFF's `dtFields` capability line is an observation of what the service answered, never a statement about the remote flag; the operator-confirmed flag state is recorded in the smoke document.
4. **Cache rule (BFF).** The BFF caches club defaults and offers for `STP_DATATRAK_CACHE_SECONDS` (60 s). To withdraw exposure: turn `guest-pass-online` off for the club **first** (evaluated per request, no cache), then wait the TTL or restart the pod before treating an upstream flip or rollback as withdrawn. Setting `STP_CATALOG_SOURCE=fixture` restores the mock demo, labelled as such; it is not proof that live exposure was withdrawn.
5. **Keys are named once.** The two DataTrak keys exist with exactly these names in both constants classes, both local yml files, contract §8a(e) and this runbook. A rename is a code change in two repos.
6. **No secret in any step.** The DataTrak service credential lives in the k8s secret; the BFF reads `STP_DATATRAK_SERVICE_AUTH` from the environment and never prints it; verification `curl`s read it from the shell environment (`-H "Authorization: $STP_DATATRAK_SERVICE_AUTH"`), never from a typed literal.

## Stop rules (any environment)

- A flag cannot be observed off on every instance → do not drop, do not proceed to the next flag.
- `ORA-00904` in an M&O page log after an M&O flip → the schema is incomplete for that database: flag off, back to R1/P1.
- `guest-pass.columns-absent` warn in the datatrak-service log → the service flag is on ahead of the scripts: it self-heals, but the order was wrong — flag off, back to R1/P1.
- A template-row `MERGE` collision (`CTEM_UNIQUE_BILLING`) → stop the script; Terry decides.
- Any step that would require printing or pasting the service credential → stop; read it from the environment or have the secret's owner run the step.
