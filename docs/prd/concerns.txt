Main points:
• Metrics counters belong in MetricsService (BackfillDryRun, WalletEventService, ProspectClassifier)
• ProspectClassifier -> MemberClassifier (prospect is a member type from agreement settings). Club mismatch should fail, not debug-log. isProspect should be boolean, not Integer/BigDecimal
• Drop FeatureFlagHelper#isProspectLaneEnabled — call LD getBooleanFeature directly
• Don’t re-parse UUIDs / re-validate @NotNull fields / GUID full UUID checks that already fail earlier
• Publisher: topic as a required constant (no empty default). Use JSR validation instead of IllegalStateException
• ProspectPaymentMethodChangedEventProcessor looks redundant vs PaymentMethodChangedEventProcessor. Why a custom PaymentMethod processor for prospects and no Assignment processor?
• ConsentPolicyConfiguration registers a no-op bean and likely breaks member document generation
• Too many prospect PM flags — collapse to one LD/feature flag (incl. ProspectTierInvariantGuard)
• Kafka: retry at the container, not a loop in the handler. Drop default config, custom group, String ser/de — consume a typed object
