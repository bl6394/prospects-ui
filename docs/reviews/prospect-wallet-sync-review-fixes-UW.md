## Point 1 — agreement-less MEMBER dedup key fallback behind a LaunchDarkly flag (2026-09-15)

`LaunchDarklyFeatureFlagKey.ENABLE_AGREEMENT_LESS_MEMBER_DEDUPLICATION` (`universal-wallet-PROSPECT-enable-agreement-less-member-deduplication`; `PROSPECT` stands in for the ticket token because the lane has no ticket number yet) now gates only the MEMBER branch of the id-based fallback in `DeduplicationJobKeyByWalletEntryOwnerCalculator`. The service is injected through the constructor (`@RequiredArgsConstructor`, as the neighbouring `@Component`s do). With the flag **off (the default)** a MEMBER owner without a non-blank `dt_agreementNumber` throws the pre-existing `deduplication-job.member` `NotFoundResponseError` with the pre-existing detail `MEMBER: {id} does not have agreementNumber metadata`, so member behaviour is unchanged in either state; with the flag on the owner gets `DEDUPL_ACCOUNT_MEMBER_<ownerId>` (decision D-04, plan v2 G8). The agreement-number path and the PAYOR fallback are not gated, and the owner-type guard in `WalletEntryDeduplicationJobSchedulerService.scheduleJob(WalletEntryOwner)` is deliberately left unflagged (a no-op for MEMBER and PAYOR, as argued in the response). The test LaunchDarkly file (`src/test/resources/launchdarkly/default.yml`) pins the flag to `false`, and `WalletEntryDeduplicationJobSchedulerTest` overrides it to `true` per test the same way it already does for `ENABLE_WALLET_ENTRY_DEDUPLICATION_JOB`, so the prospect add-card scheduling test still exercises the fallback. Evidence: `DeduplicationJobKeyByWalletEntryOwnerCalculatorTest` grew from 13 to 20 data-provider rows and now carries a flag column: five agreement-less MEMBER shapes (absent, null, empty, whitespace agreement, prospect marker only) are asserted for both states (key when on, exact error code plus detail when off), and the agreement path and PAYOR fallback are asserted independent of the flag. `./gradlew test --tests '*Deduplication*'`: 38 tests, 0 failures (calculator 20, scheduler 16, job 2). `./gradlew compileJava compileTestGroovy`: clean. Full `./gradlew test`: 978 tests in 119 classes, 0 failures, 0 errors, 0 skipped (about 3.5 minutes on JDK 25). **Rollout:** the flag defaults to off in every environment. Turn it on per environment together with the prospect lane (`wallet-account-sync-prospect-lane` and the `STP_WALLET_WRITES` day-pass writer); until then prospect owners keep failing dedup key calculation exactly as before this sprint (the G8 canary keeps logging `deduplication-job.member`), and if the fallback key misbehaves after enablement it is switched off without a deploy. Readiness register: L3 line to reference this flag.
