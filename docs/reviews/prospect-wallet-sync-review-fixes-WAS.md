## CI fix (PR #406)

**Failure.** GitHub Actions job 104570827203: `ProspectLaneIntakeSideTest > realHttpRoutesProspectsAndPreservesMemberConsent[0](false, false)` threw `TimeoutException` at `getKafkaMessages(topic, 1)` (line 95). 1087 tests, 1 failed; the same commit was fully green locally.

**Root cause (test infrastructure, not product).** `BaseKafkaTest.setupKafka` in common-unit-test 41.4.1 starts the test consumer container and waits only for `container.isRunning()`, never for the consumer-group rebalance that assigns partitions, and leaves `auto.offset.reset` at Kafka's default `latest`. The `(false, false)` case is the first method run in the class and publishes within milliseconds of setup, so on the slow CI runner the record was produced before the `automated-test-consumer` group owned `local.prospect-proof.intake` and was never delivered. The production side is synchronous (`ProspectWalletSyncEventPublisher` blocks on the broker ack before the webhook returns 200), so there is no product race. Upstream common-unit-test 42.6.0 already fixed this with a per-class group id and `ContainerTestUtils.waitForAssignment`; this repo pins 41.4.1.

**Change.** `src/test/groovy/com/abcfinancial/api/walletaccountsync/WaSyncBaseKafkaTest.groovy`: new `@BeforeClass(dependsOnMethods = "setupKafka") awaitKafkaConsumerAssignment()` that blocks with Awaitility (60 s bound, 200 ms poll) until the container has an assigned partition for every topic in `kafkaListenTopics()`. Applies to all six Kafka-base subclasses. No assertions, timeouts or retry semantics were weakened; no sleeps added.

**Evidence.** `./gradlew test --tests '*ProspectLaneIntakeSideTest*'` green 3 times in a row after the change (3/3 each); `./gradlew test --tests '*Prospect*' --tests '*MemberLane*'` green once: 27 classes, 240 tests, 0 failures. Baseline run before the change also passed locally (the race is CI-only).
